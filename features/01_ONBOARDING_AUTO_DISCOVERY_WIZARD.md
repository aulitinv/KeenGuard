# План реализации: Мастер первого запуска (Onboarding & Auto-Discovery Wizard)

## 1. Цель и назначение
Сделать первый контакт пользователя с KeenGuard максимально простым и бесшовным. Устранить необходимость ручного поиска IP-адреса роутера, протоколов и глубоких настроек при первом запуске.

---

## 2. Архитектура и этапы работы мастера

Мастер запускается автоматически в виде модального экрана при первом открытии веб-интерфейса (`http://localhost:9989`), если в конфигурации `onboarding_completed == false`.

## 3. Детальные инженерные спецификации

### Шаг 1: Автоопределение шлюза и платформы (Auto-Discovery)
- **Бэкенд**:
  - Определение шлюза через Scapy `conf.route.route("8.8.8.8")[2]` с резервным перебором типовых домашних адресов (`192.168.1.1`, `192.168.0.1`, `192.168.2.1`, `10.0.0.1`).
  - Быстрый асинхронный HTTP probe с коротким тайм-аутом (1.0 сек):
    - `GET http://{ip}/auth` — если ответ содержит заголовок `X-NDM-Challenge` или заголовок realm Keenetic, платформа идентифицируется как **`Keenetic`** (порт 80, логин `admin`).
    - `POST http://{ip}/ubus` — если возвращается валидный JSON-RPC, платформа идентифицируется как **`OpenWrt`** (порт 80, логин `root`).
  - Эндпоинт `POST /api/onboarding/detect-router` возвращает:
    ```json
    {
      "status": "ok",
      "detected": true,
      "ip": "192.168.1.1",
      "platform": "keenetic",
      "platform_name": "KeeneticOS",
      "default_username": "admin"
    }
    ```
- **Фронтенд**:
  - Анимированный статус поиска: *«Сканируем домашний шлюз...»* $\rightarrow$ *«Обнаружен роутер Keenetic на 192.168.1.1»*.
  - Поля IP, платформы и логина заполняются автоматически. Пользователь вводит только пароль.
  - Кнопка «Проверить связь» валидирует учетные данные.

### Шаг 2: Проверка Npcap / libpcap
- Проверка через `conf.use_pcap` в Scapy:
  - Если `True`: зеленый бейдж *«Драйвер перехвата пакетов активен. Защита от L2-аномалий готова к работе»*.
  - Если `False`: информационная карточка *«Npcap не обнаружен. Роутер будет опрашиваться штатно, но для глубокого анализа сетевых пакетов рекомендуется установить Npcap»* + прямая ссылка на `https://npcap.com/#download`.

### Шаг 3: Пресеты защиты «В один клик»
- При выборе пресета бэкенд сразу применяет набор параметров:
  - **Сбалансированный**:
    - Включение DNS Sinkhole для Smart TV (пресеты блокировки рекламы и телеметрии Samsung ACR, LG Smart Ad, Xiaomi MiStat).
    - Автоматический аудит UPnP с закрытием опасных портов (554 RTSP, 80/8080).
    - Уведомления о появлении новых устройств.
  - **Строгий**:
    - Все настройки Сбалансированного + `new_device_quarantine_wan = True` (новые устройства не выходят в интернет до одобрения).
    - Ночной режим для Smart TV с 00:00 до 07:00.
  - **Базовый**:
    - Только сбор телеметрии, без активных правил блокировки.

### Шаг 4: Telegram (Опционально)
- Ввод токена бота и Chat ID.
- Кнопка «Отправить тестовое сообщение» для мгновенной проверки связи.
- Кнопка «Пропустить» для тех, кому не нужны уведомления в мессенджер.

## 4. Новые API-эндпоинты

| Метод | Эндпоинт | Назначение |
|---|---|---|
| `GET` | `/api/onboarding/status` | Проверка завершенности мастера, состояния роутера и наличия pcap |
| `POST` | `/api/onboarding/detect-router` | Авто-определение шлюза и типа роутера в сети |
| `POST` | `/api/onboarding/complete` | Сохранение настроек роутера, применение пресета, завершение онбординга |
| `POST` | `/api/onboarding/reset` | Сброс флага онбординга для повторного запуска мастера из Настроек |
