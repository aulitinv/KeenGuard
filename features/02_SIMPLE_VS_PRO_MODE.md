# План реализации: Режим интерфейса «Простой» vs «Эксперт» (Simple vs Pro Mode)

## 1. Цель и назначение
Снизить когнитивную нагрузку на пользователей-новичков, сохранив при этом всю глубину инструментария для сетевых инженеров и специалистов по безопасности.

Обычному пользователю важно знать:
- «Всё ли в порядке с моей домашней сетью?»
- «Кто сейчас подключен к Wi-Fi?»
- «Не шпионит ли телевизор или камера?»
- «Как отключить подозрительное устройство в 1 клик?»

Сложные термины (блок Hex-дампов пакетов, Conntrack flows, ARP-инспекция, сырые PCAP-кольца, L2 broadcast штормы) в базовом режиме скрываются, но мгновенно доступны при переключении тумблера в режим «Эксперт».

## 2. Концепция интерфейса и UX

### Переключатель в шапке (Header Toggle)
В верхнюю панель навигации (рядом с индикатором статуса роутера) добавляется компактный двухпозиционный переключатель с плавной анимацией:
```
[ 🛡️ Простой | ⚙️ Эксперт ]
```
Состояние сохраняется в `localStorage.getItem('keenguard_ui_mode')` (по умолчанию `simple` для новых пользователей).

## 4. Архитектура и техническая реализация

### Фронтенд (`app.js` и `index.html`)
1. **CSS-класс на контейнере верхнего уровня**:
   - При смене режима на элемент `<body>` навешивается класс: `mode-simple` или `mode-pro`.
   - Разделы, предназначенные только для экспертов, помечаются атрибутом `data-pro-only="true"`:
     ```css
     body.mode-simple [data-pro-only="true"] {
         display: none !important;
     }
     ```
2. **Адаптивные компоненты**:
   - Таблица устройств переключается между режимами карточек (`card-view` в Simple) и компактной плотной таблицы (`data-table` в Pro).
   - Термины заменяются через дата-атрибуты или JS-транслятор:
     * *«Спуфинг ARP / Gratuitous ARP»* $\rightarrow$ *«Конфликт сетевого адреса»*
     * *«LAA MAC Randomization»* $\rightarrow$ *«Случайный адрес (защита приватности смартфона)»*
     * *«UPnP IGD Forwarding 554/TCP»* $\rightarrow$ *«Камера доступна из интернета без пароля»*

### Бэкенд (`keenguard/web/app.py`)
- API предоставляет единый набор данных, но добавляет поля человекочитаемых описаний (`human_description`, `threat_level_label`, `plain_recommendation`), чтобы фронтенду в простом режиме не требовалось парсить сложные сетевые структуры.
- Эндпоинт `/api/settings/ui-mode`: сохранение предпочтений пользователя в глобальном профиле.

## 5. Технический реализм (AGENTS.md Compliance)
- В простом режиме запрещено показывать плацебо-статусы вроде «Устройство полностью защищено», если оно находится в общем L2-мосте `Bridge0`.
- Вместо этого формулировка:
  > *«Выход в интернет ограничен правилом роутера. Для изоляции от других домашних компьютеров подключите устройство к Гостевой Wi-Fi сети»*.
- Четкое разделение понятий: «Выключен экран» vs «Режим дежурного сна с активной сетью (Standby)».

## 6. План тестирования
1. **Тест переключения режима**: Проверка сохранения значения в `localStorage` и корректного добавления класса `mode-simple` / `mode-pro`.
2. **Тест скрытия Pro-элементов**: Проверка, что при активном `mode-simple` вкладки инспектора пакетов и сбора PCAP не отображаются в DOM-дереве навигации.
3. **Тест адаптации терминов**: Валидация вывода человекочитаемых подсказок для критических предупреждений.
