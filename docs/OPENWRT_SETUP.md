# Инструкция по подключению роутеров OpenWrt к KeenGuard

Данное руководство содержит пошаговые инструкции по подключению и настройке роутеров под управлением **OpenWrt** к системе сетевой безопасности **KeenGuard**.

---

## 1. Таблица совместимости версий

KeenGuard взаимодействует с OpenWrt через системную шину **`ubus` JSON-RPC** и подсистему **UCI**, что обеспечивает стабильную работу на широком диапазоне версий:

| Версия OpenWrt | Менеджер пакетов | Файрвол ядра | Статус поддержки | Примечания |
|---|:---:|:---:|:---:|---|
| **OpenWrt 25.x (Snapshots)** | **`apk`** | `firewall4` (nftables) | ✅ Полная | Новый менеджер пакетов `apk` (Alpine Package Keeper), ядро Linux 6.6 / 6.12 |
| **OpenWrt 24.10** | `opkg` | `firewall4` (nftables) | ✅ Полная | Ядро Linux 6.6, стандартный `opkg` |
| **OpenWrt 23.05** | `opkg` | `firewall4` (nftables) | ✅ Полная | Ядро Linux 5.15, современный LuCI RPC |
| **OpenWrt 22.03** | `opkg` | `firewall4` (nftables) | ✅ Полная | Первый релиз на `fw4` и `nftables` |
| **OpenWrt 21.02** | `opkg` | `firewall3` (iptables) | ✅ Полная | Поддерживаются DSA-архитектура и legacy iptables |
| **OpenWrt 19.07** | `opkg` | `firewall3` (iptables) | ⚠️ Базовая | Базовый опрос хостов и WAN-блокировка; некоторые RPC-методы могут отсутствовать |
| **OpenWrt ≤ 18.06** | `opkg` | `firewall3` (iptables) | ❌ Не поддерживается | Устаревшие API и синтаксис netifd |

## 2. Разница пакетных менеджеров: `opkg` vs `apk` (OpenWrt 25+)

Начиная с **OpenWrt 25.x (25.12+)**, проект OpenWrt перешел с устаревшего менеджера `opkg` на современный **`apk`** (`apk-tools`):

| Действие | OpenWrt 21.02 – 24.10 (`opkg`) | OpenWrt 25.x (`apk`) |
|---|---|---|
| Обновить списки репозиториев | `opkg update` | `apk update` (или ключ `-U`) |
| Установить пакет(ы) | `opkg install <пакет>` | `apk add <пакет>` (или `apk -U add <пакет>`) |
| Поиск пакета | `opkg find <маска>` | `apk search <маска>` |
| Проверка установленного пакета | `opkg list-installed \| grep <имя>` | `apk info <имя>` |

> **Внимание для пользователей OpenWrt 25+:**  
> Команда `apk upgrade` для обновления всей системы не рекомендуется к использованию разработчиками OpenWrt, так как может нарушить зависимости ядра. Для обновления прошивки используйте Attended Sysupgrade или образ с официального Firmware Selector.

## 3. Необходимые пакеты на роутере

Для работы KeenGuard со всеми функциями (опрос клиентов, статистика NAT, управление WAN/DNS/IP-блэкхолами, захват дампов) требуются следующие компоненты:

### Если у вас стандартная прошивка с веб-интерфейсом LuCI
В большинстве готовых сборок OpenWrt с LuCI уже установлены веб-сервер `uhttpd`, шина `rpcd`, модули `rpcd-mod-uci` и `rpcd-mod-file`.  
Вам остается установить только модуль RPC-интерфейсов и утилиту захвата пакетов:

#### Для OpenWrt 25.x (`apk`):
```bash
apk -U add luci-mod-rpc tcpdump-mini
```

#### Для OpenWrt 21.02 — 24.10 (`opkg`):
```bash
opkg update
opkg install luci-mod-rpc tcpdump-mini
```

---

### Если у вас минималистичный headless-образ (без LuCI)
Установите минимальный набор служб для работы `/ubus`:

#### Для OpenWrt 25.x (`apk`):
```bash
apk -U add uhttpd uhttpd-mod-ubus rpcd rpcd-mod-uci rpcd-mod-file luci-mod-rpc tcpdump-mini
/etc/init.d/uhttpd enable
/etc/init.d/uhttpd start
/etc/init.d/rpcd restart
```

#### Для OpenWrt 21.02 — 24.10 (`opkg`):
```bash
opkg update
opkg install uhttpd uhttpd-mod-ubus rpcd rpcd-mod-uci rpcd-mod-file luci-mod-rpc tcpdump-mini
/etc/init.d/uhttpd enable
/etc/init.d/uhttpd start
/etc/init.d/rpcd restart
```

## 4. Настройка подключения в веб-интерфейсе KeenGuard

1. Запустите KeenGuard (`run.py` или `start.bat`) и откройте веб-интерфейс:  
   👉 **[http://localhost:9989](http://localhost:9989)**
2. Перейдите в левом меню в раздел **«Настройки» → вкладка «Роутер»**.
3. В блоке **«Платформа роутера»** переключите селектор на:  
   🔘 **OpenWrt (ubus)**
4. Заполните параметры подключения:
   - **Хост роутера:** IP-адрес роутера в локальной сети (по умолчанию `192.168.1.1`).
   - **Порт:** `80` (для стандартного HTTP) или `443` (при использовании HTTPS/SSL).
   - **Протокол:** отметьте чекбокс **HTTPS**, если на роутере настроен сертификат SSL.
   - **Путь ubus:** оставьте `/ubus` (стандартный путь).
   - **Пользователь:** `root`.
   - **Пароль:** пароль учетной записи `root` от веб-интерфейса LuCI / SSH.
5. Нажмите кнопку **«Проверить связь с роутером»**.
   - Система выполнит тестовый вход (`session login`) и вернет модель оборудования и версию ОС.
6. Нажмите **«Сохранить настройки роутера»**.

## 5. Как работают защитные механизмы KeenGuard на OpenWrt

В соответствии с правилами инженерного реализма, все функции работают на физическом и системном уровне без эмуляций:

### 1. Блокировка доступа в Интернет (WAN Quarantine / Zero Internet)
- При блокировке устройства KeenGuard через ubus добавляет в файл конфигурации `/etc/config/firewall` именованное правило:
  ```
  config rule
      option name 'keenguard_block_00_aa_bb_cc_dd_ee'
      option src 'lan'
      option dest 'wan'
      option src_mac '00:AA:BB:CC:DD:EE'
      option target 'DROP'
  ```
- Затем выполняется `uci commit firewall` и перезагрузка правил файрвола.
- На версиях OpenWrt 22+ (включая 25.x) демон `firewall4` мгновенно транслирует это правило в цепочки `nftables`.

### 2. DNS Sinkhole (0.0.0.0)
- Домены трекеров, рекламы и телеметрии ТВ блокируются на уровне встроенного `dnsmasq`:
  ```
  uci add_list dhcp.@dnsmasq[0].address='/samsungacr.com/0.0.0.0'
  uci commit dhcp
  /etc/init.d/dnsmasq reload
  ```

### 3. Аппаратный IP Blackhole (L3)
- Для мгновенной блокировки вредоносных внешних IP-адресов создаются правила `REJECT` в зоне WAN:
  ```
  config rule
      option name 'keenguard_blackhole_198_51_100_1'
      option src 'lan'
      option dest 'wan'
      option dest_ip '198.51.100.1'
      option target 'REJECT'
  ```

### 4. Захват пакетов (PCAP)
- По нажатию «Начать аудит» KeenGuard запускает процесс `tcpdump` на интерфейсе сетевого моста `br-lan` с фильтрацией по IP целевого устройства.
- По завершении сессии файл дампа читается через `ubus file read` в формате base64, сохраняется локально в базу KeenGuard, а временный файл `/tmp/keenguard_capture.pcap` на роутере удаляется.

## 6. Физическая сегментация сети: Важное предупреждение (L2 vs L3)

> **Физика локальной сети (L2-обход):**  
> Все клиенты, находящиеся в стандартном мосте `br-lan` (`192.168.1.0/24`), передают трафик друг другу **напрямую по MAC-адресам через сетевой мост (коммутатор) роутера**. Этот трафик физически не попадает в файрвол (`nftables` / `iptables`).
> 
> Если китайская камера или телевизор подключены к вашей основной сети Wi-Fi, они могут сканировать ваши домашние компьютеры и NAS, даже если выход в интернет для них заблокирован.

### Рекомендация по надежной изоляции:
1. Создайте в OpenWrt отдельный беспроводной интерфейс (гостевую сеть, например `guest`) в меню **Network → Wireless**.
2. Обязательно включите опцию изоляции клиентов:
   ```
   option isolate '1'
   ```
3. Привяжите гостевую сеть к изолированному интерфейсу с отдельной подсетью (например, `192.168.2.0/24`), запретив маршрутизацию в зону `lan`.
4. Подключайте подозрительную технику (камеры, телевизоры, розетки) исключительно к этой изолированной сети. Вкладка **«Безопасность → Сегменты сети»** в KeenGuard автоматически проверит корректность сегментации.

## 7. Диагностика неисправностей (Troubleshooting)

| Проблема | Причина | Решение |
|---|---|---|
| **Ошибка подключения: HTTP 404** | Не активен ubus-эндпоинт на веб-сервере роутера | Убедитесь, что установлен пакет `uhttpd-mod-ubus` и служба перезапущена: `/etc/init.d/uhttpd restart` |
| **HTTP 403 / Access Denied** | Неверный логин или пароль `root` | Проверьте пароль через веб-интерфейс LuCI или вход по SSH. Убедитесь, что учетная запись `root` не заблокирована. |
| **Захват трафика выдает ошибку** | Не установлен `tcpdump` | Установите пакет: `apk -U add tcpdump-mini` (для 25.x) или `opkg install tcpdump-mini` (для 21–24.x). |
| **Пустой список активных сессий NAT** | Отсутствует модуль conntrack RPC | Установите пакет `luci-mod-rpc`. |
| **Ошибка SSL-сертификата (HTTPS)** | На роутере используется самоподписанный сертификат LuCI | В KeenGuard встроен обход проверки недоверенных локальных сертификатов (`verify=False` для локальных IP), проверьте корректность порта (`443`). |
