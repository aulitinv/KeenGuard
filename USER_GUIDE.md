## 1. Введение и архитектурные принципы

KeenGuard — это специализированная система мониторинга безопасности, созданная специально для интернет-центров **Keenetic** под управлением KeeneticOS 3.x / 4.x. В отличие от тяжелых облачных решений или модифицированных прошивок (OpenWrt), KeenGuard работает рядом с роутером на локальном сервере/ПК, взаимодействуя с роутером через официальный встроенный протокол RCI (Remote Control Interface) и слушая широковещательный трафик локального сегмента.

```
┌───────────────────────────────────────────────────────────┐
│                    Домашняя сеть                          │
│                                                           │
│  [Smart TV]  [Смартфон]  [IP-Камера]  [IoT Розетки]       │
│      │           │            │            │              │
│      └───────────┴─────┬──────┴────────────┘              │
│                        │ L2 Broadcast/Multicast           │
│                        ▼                                  │
│         ┌───────────────────────────────┐                 │
│         │   KeenGuard Сервер (Python)   │                 │
│         │  - Scapy (Пассивный сниффер)  │                 │
│         │  - SQLite (База инцидентов)   │                 │
│         │  - Web UI (Порт 9989)         │                 │
│         └──────────────┬────────────────┘                 │
│                        │ HTTP RCI API (CLI/JSON)          │
│                        ▼                                  │
│         ┌───────────────────────────────┐                 │
│         │   Роутер Keenetic (Gateway)   │                 │
│         │  - DNS-прокси (0.0.0.0)       │                 │
│         │  - NAT & UPnP таблицы         │                 │
│         │  - Сегменты (Bridge0, Guest)  │                 │
│         └──────────────┬────────────────┘                 │
│                        │ WAN                              │
│                        ▼                                  │
│                   [ Интернет ]                            │
└───────────────────────────────────────────────────────────┘
```

### Технический реализм: L2 vs L3 и физическая сегментация

Важнейший инженерный принцип KeenGuard: **полная честность перед пользователем и отсутствие «плацебо-безопасности»**.

1. **Уровень L2 (Внутри коммутатора Bridge0):**
   * Все устройства, подключенные к основной домашней сети (`192.168.1.0/24`), коммутируются на канальном уровне (L2) напрямую через встроенный свитч роутера или по Wi-Fi.
   * Трафик между двумя устройствами в одном сегменте **не проходит через сетевой фильтр (iptables) роутера**. Никакой программный флаг в интерфейсе не может предотвратить прямую атаку между ними внутри одного L2-домена.
   * **Реальная защита:** Для надежной изоляции подозрительное устройство (умная колонка, китайская камера, ТВ) необходимо перевести в отдельный изолированный сегмент роутера (например, «Гостевой сегмент» или отдельный IoT VLAN). KeenGuard подсказывает, как это сделать, через *Аппаратный советник сегментации*.

2. **Уровень L3 (Маршрутизация и интернет):**
   * Весь трафик, идущий во внешнюю сеть (WAN), проходит через роутер Keenetic.
   * Здесь роутер обладает абсолютным аппаратным контролем: блокировка выхода в интернет (WAN block), закрытие UPnP-пробросов, принудительное завершение соединений и подмена DNS-ответов.

3. **Аппаратный DNS-фильтр (0.0.0.0 Sinkhole):**
   * KeenGuard не устанавливает тяжелых внешних DNS-демонов. Блокировка рекламы и трекеров осуществляется нативно командами `ip host <domain> 0.0.0.0` прямо в ядро сетевого DNS-прокси интернет-центра Keenetic.

### Пассивный сниффинг и прямое RCI-взаимодействие

* **Нулевая нагрузка на сеть:** KeenGuard не шлет агрессивных пингов и сканов на устройства, чтобы не будить спящие гаджеты и не забивать эфир Wi-Fi.
* **Чтение памяти роутера:** Список устройств, активных сессий и соединений запрашивается напрямую из ОЗУ роутера (`/rci/show/ip/hotspot`).
* **Пассивный сниффер (Scapy):** Фоновый анализатор слушает только широковещательные пакеты, циркулирующие по сети:
  * Wake-on-LAN (UDP 7/9)
  * mDNS / Bonjour (UDP 5353)
  * SSDP / UPnP (UDP 1900)
  * ARP-запросы (для выявления скрытого сканирования сети приложениями)

## 2. Системные требования и быстрый старт

### Системные требования
* **ОС:** Windows 10/11, Windows Server, Linux или macOS.
* **Python:** Версия 3.11 – 3.13.
* **Поддерживаемые роутеры:**
  - **Keenetic:** интернет-центры под управлением KeeneticOS 3.5 или выше (с правами администратора).
  - **OpenWrt:** версии 21.02, 22.03, 23.05, 24.10, 25.x (требуются пакеты `uhttpd-mod-ubus`, `luci-mod-rpc`, `tcpdump-mini`). Подробнее см. [docs/OPENWRT_SETUP.md](docs/OPENWRT_SETUP.md).
* **Сетевой драйвер:** Для Windows необходим установленный драйвер **Npcap** (для захвата сетевых пакетов через Scapy).

### Установка Npcap
1. Скачайте бесплатный установщик [Npcap](https://npcap.com/#download).
2. При установке обязательно отметьте пункт: **«Install Npcap in WinPcap API-compatible Mode»**.
3. Завершите установку. Перезагрузка обычно не требуется.

### Запуск приложения

#### Способ 1: Готовый командный файл
В корневой папке проекта дважды кликните по файлу:
```
start.bat
```
Скрипт автоматически активирует виртуальное окружение Python и запустит сервер.

#### Способ 2: Через PowerShell / Командную строку
```powershell
# Перейдите в каталог проекта
cd C:\path\to\network_sec

# Запустите сервер через виртуальное окружение
.\venv\Scripts\python.exe run.py
```

После запуска в консоли появится сообщение:
```
INFO: Uvicorn running on http://0.0.0.0:9989 (Press CTRL+C to quit)
```
Откройте в любом браузере адрес: **[http://localhost:9989](http://localhost:9989)** (или `http://IP_ВАШЕГО_ПК:9989` с любого устройства в локальной сети).

### Первоначальное подключение к роутеру (Keenetic / OpenWrt)
1. Откройте веб-интерфейс и перейдите во вкладку **«Настройки» → «Роутер»** (или кликните на статус-бейдж роутера в шапке).
2. Выберите платформу вашего роутера:
   - **Keenetic (RCI):** укажите IP-адрес роутера (по умолчанию `192.168.1.1`), логин администратора (`admin`) и пароль.
   - **OpenWrt (ubus):** укажите IP-адрес роутера, порт (`80`/`443`), протокол HTTP/HTTPS, логин (`root`) и пароль. Подробные инструкции по настройке OpenWrt см. в [docs/OPENWRT_SETUP.md](docs/OPENWRT_SETUP.md).
3. Нажмите кнопку **«Проверить связь с роутером»**. При успешной авторизации статус в шапке сменится на зеленый с отображением реальной модели роутера, версии ОС и задержки RTT.
4. Нажмите **«Сохранить настройки роутера»**.

### Горячие клавиши и управление интерфейсом
* Клавиша **`[`** (квадратная скобка): Быстрое сворачивание и разворачивание левого бокового меню для максимизации рабочего пространства таблиц и графиков.
* **Адаптивный интерфейс:** На мобильных устройствах и планшетах доступна кнопка бургер-меню в шапке.

## 3. Подробный обзор функционала по разделам

Интерфейс KeenGuard организован в виде 10 специализированных рабочих пространств в левом меню навигации, а также развернутого центра конфигурации.

### 3.1. Дашборд (Центр оперативного обзора и экспресс-аудиты)
Главный экран служит центром оперативного информирования:
* **Индикатор связи с Keenetic:** В верхнем правом углу отображается статус онлайн/офлайн роутера с временем отклика в миллисекундах. При потере связи выводится предупреждающий баннер.
* **Ключевые метрики:** Количество активных клиентов онлайн, распределение по профилям (ТВ, IoT, Смартфоны, Камеры), число активных правил блокировки Sinkhole и инцидентов безопасности.
* **Живой график трафика (Live Traffic Chart):** В реальном времени с секундным шагом рисует графики входящей (Download) и исходящей (Upload) скорости всей сети.
* **Экспресс-аудит безопасности Wi-Fi:** Анализирует настройки беспроводных сетей роутера:
  * Проверка протоколов шифрования (WPA3 / WPA2-Enterprise / устаревший небезопасный WPA1/WEP);
  * Проверка уязвимого протокола WPS (Wi-Fi Protected Setup);
  * Наличие открытых или беспарольных гостевых сетей;
  * Рекомендации по оптимизации безопасности.
* **Проверка обновлений KeeneticOS:** Опрашивает официальный сервер Keenetic и показывает наличие свежей стабильной или Preview-версии прошивки интернет-центра.
* **Суточный дайджест безопасности:** Кнопка быстрого просмотра и ручной отправки отчета в Telegram.

---

### 3.2. Безопасность (Security Checklist и Советник сегментации)
Раздел объединяет комплексную диагностику уязвимостей сети и рекомендации по архитектурному разделению:
* **Интерактивный чеклист безопасности:** Проверка ключевых параметров защиты периметра (активность UPnP, защита паролем, наличие изолированного сегмента, блокировка небезопасных протоколов).
* **Аппаратный советник сегментации (Hardware Segmentation Advisor):**
  * Опрашивает аппаратную конфигурацию сегментов интернет-центра (`Bridge0`, `Guest`, дополнительные VLAN).
  * Сопоставляет типы подключенных устройств с сегментами, в которых они находятся.
  * Если умные датчики, китайские IP-камеры или смарт-ТВ находятся в основном сегменте `Bridge0` вместе с вашими рабочими ноутбуками, домашними NAS и телефонами, советник маркирует ситуацию как **критический риск**.
  * Выдает конкретную пошаговую инструкцию: как создать отдельный Wi-Fi сегмент «Умный дом», включить межсегментную изоляцию и безопасно мигрировать устройства.

### 3.3. Устройства (Инспектор узлов, LAA-рандомизация и карточка хоста)
Центральная таблица всех сетевых узлов, зафиксированных роутером Keenetic:
1. **Умное распознавание вендора и типа устройства:** По префиксу аппаратного адреса (IEEE OUI) и анализу сетевого поведения система автоматически классифицирует тип оборудования: Roborock, Яндекс Станция, Apple, Samsung, Tuya, Espressif, LG webOS и др.
2. **Детектор частных / рандомизированных MAC (LAA):** 
   * Современные ОС (iOS 14+, Android 10+, Windows 11) по умолчанию подменяют реальный аппаратный адрес на виртуальный (Locally Administered Address).
   * KeenGuard мгновенно распознает LAA-адреса по специальному биту в первом байте MAC и выводит предупреждение.
   * Система умеет ассоциировать сменяющиеся MAC-адреса с одним и тем же физическим устройством по совпадению сетевого имени (hostname).
3. **Профилирование безопасности:**
   * **Smart TV:** Асимметричный режим — стриминг разрешен, но доступ к файловым шарам LAN запрещен.
   * **IoT Zero Internet:** Запрет выхода в глобальный интернет для китайских умных розеток, датчиков и реле.
   * **NVR Only (Камеры):** Блокировка доступа камеры к облаку с сохранением вещания на локальный видеорегистратор (NVR/NAS).
   * **Доверенный контроллер:** Смартфоны администратора с правом управления медиа-потоками.
4. **Управление доступом в один клик:** 
   * Блокировка доступа в интернет (WAN Block);
   * Изоляция клиента.
5. **Глубокая карточка устройства:** Нажатие на строку открывает детальное окно:
   * Физические параметры подключения (порт роутера, диапазон Wi-Fi 2.4/5 ГГц, уровень сигнала RSSI, скорость линка);
   * Объемы переданных байт за всё время;
   * Список открытых сетевых соединений (с кем общается устройство прямо сейчас);
   * **GeoIP и облачные провайдеры:** Определение страны и хостинг-провайдера удаленных IP-адресов (Amazon AWS, Cloudflare, Яндекс, VK, Microsoft Azure и др.);
   * История трафика и экспорт данных в CSV / JSON.

### 3.4. Умный дом (Защита IoT-хабов и политика Zero-Internet)
Специализированный экран контроля экосистемы автоматизации (Home Assistant, SprutHub, шлюзы Zigbee/Matter/Wi-Fi):
* **Аудит центральных IoT-хабов:** Контроль сетевой активности управляющих шлюзов, проверка наличия открытых веб-панелей без авторизации.
* **Политика Zero-Internet:** Возможность перевода всех исполнительных устройств (умные розетки, реле, выключатели Tuya, Sonoff, Shelly) в полностью локальный режим без выхода в зарубежные облака. Локальное управление через хаб по MQTT/CoAP сохраняется на 100%.
* **Контроль облачных потоков:** Выявление скрытых попыток связи с неавторизованными серверами телеметрии.

---

### 3.5. Локальная сеть (Матрица взаимодействия и Lateral Movement)
Раздел мониторинга межузлового трафика внутри домашнего периметра:
* **Матрица межузловых связей (LAN Communications Matrix):** Наглядная таблица того, кто с кем общается внутри домашней подсети.
* **Обнаружение перемещения внутри периметра (Lateral Movement):** Фиксация ситуаций, когда скомпрометированное IoT-устройство пытается установить контакт с домашним компьютером или сетевым хранилищем NAS.
* **Контроль LAN-пресетов:** Применение правил взаимодействия между группами устройств.

---

### 3.6. Инспектор пакетов (Deep Packet Inspector & Live Hex Viewer)
Полнофункциональный встроенный веб-анализатор сетевых пакетов (в стиле современного веб-Wireshark), доступный прямо в браузере.

#### Трехпанельный интерфейс анализа:
1. **Верхняя панель — Список перехваченных пакетов (Packet List):**
   * Выводит перехваченные пакеты в реальном времени с точным временем, MAC/IP источника и назначения, протоколом, длиной и краткой сводкой (Info).
   * **Управление захватом:** Кнопка **«Пауза / Возобновить»** позволяет заморозить поток для спокойного изучения интересующего пакета без вытеснения новыми кадрами.
   * **Умные фильтры:** Быстрая фильтрация по конкретному устройству сети и по протоколам (**DNS**, **NTP**, **HTTP**, **MQTT**, **TLS**, **SSDP / mDNS**, **ARP**, **ICMP**).
2. **Нижняя левая панель — Дерево уровней модели OSI (Packet Details Tree):**
   * Раскрывающееся дерево слоев пакета с подробным декодированием заголовков:
     * **Уровень L2:** Ethernet II (MAC-адреса, Type);
     * **Уровень L3:** IPv4 / IPv6 (TTL, флаги фрагментации, контрольные суммы);
     * **Уровень L4:** TCP / UDP / ICMP (порты, Sequence/Ack, флаги SYN/ACK/FIN, оконные параметры);
     * **Уровень приложений (L7):** Распознавание полезной нагрузки протоколов умного дома и интернета (декодирование DNS-запросов и ответов, NTP-таймстампов, тем и полезной нагрузки MQTT, заголовков HTTP, SNI в TLS ClientHello).
3. **Нижняя правая панель — Интерактивный Hex & ASCII дамп (Packet Bytes):**
   * Классический шестнадцатеричный 16-байтный дамп полезной нагрузки пакета.
   * **Интерактивная подсветка:** При наведении мыши на байты отображается их точное смещение (Offset).
   * Кнопка **«Копировать Hex»** позволяет мгновенно скопировать шестнадцатеричную строку в буфер обмена для анализа или воспроизведения.

#### Загрузка внешних дампов (.PCAP):
* Кнопка **«Открыть PCAP»** позволяет загрузить любой внешний файл `.pcap`, `.pcapng` или `.cap` прямо в веб-интерфейс и исследовать его с помощью трехпанельного просмотрщика без установки стороннего ПО.
* Архитектура построена на кольцевых буферах памяти (`PacketRingBuffer`), что гарантирует нулевую утечку оперативной памяти (Zero RAM Leak).

### 3.7. Smart TV & Forensics (Асимметричная изоляция и ночное окно)
Умные телевизоры (LG webOS, Samsung Tizen, Android TV) часто ведут себя аномально: они просыпаются посреди ночи, шлют телеметрию, сканируют домашнюю сеть и передают данные о просмотренных фильмах (технология ACR — Automatic Content Recognition).

KeenGuard ведет круглосуточную форензику:
* **Мониторинг ночного окна (по умолчанию 00:00 – 07:00):** Любая сетевая активность телевизора в эти часы берется на особый учет.
* **Умный ночной режим (Smart Night Mode):**
  * *Отсрочка по активности:* Если в момент наступления ночи телевизор транслирует трафик или был активен в течение последних 5 минут (настраиваемый порог), включение ночного режима автоматически откладывается, чтобы не прерывать просмотр.
  * *Аппаратная блокировка WAN:* При активации ночного режима роутер может автоматически отключать телевизору выход в интернет (`night_mode_auto_block_wan`), полностью предотвращая ночной фоновый трафик и рекламу.
  * *Утренний контроль:* Если телевизор так и не перешел в режим ожидания за ночь, система отправляет оповещение в Telegram и журнал событий.
* **Анализ триггера пробуждения:** Система точно определяет, почему ТВ вышел в сеть:
  * **Wake-on-LAN:** Зафиксирован магический пакет с указанием точного IP и MAC адреса устройства, которое его разбудило (например, смартфон включил ТВ по Wi-Fi);
  * **Cast / DIAL / AirPlay:** Кто-то отправил видеопоток с мобильного приложения;
  * **Автономное пробуждение:** ТВ включил сетевую карту сам по внутреннему таймеру (для скачивания обновлений или отправки фоновой аналитики);
  * **Quick Start+ (Дежурный режим):** ТВ не обесточил процессор, а продолжает периодический фоновый обмен пакетами.
* **Автоматический дамп сетевого трафика (.pcap):** При фиксации ночной аномалии кольцевой буфер автоматически записывает сетевой дамп инцидента, который можно скачать прямо из браузера и открыть в Wireshark.

### 3.8. Инциденты & UPnP (Аудит портов камер и сетевые аномалии)
KeenGuard непрерывно анализирует сетевые аномалии и риски UPnP:
* **Аудит UPnP и защита IP-камер:**
  * Дешевые камеры и видеорегистраторы часто открывают наружу порты `554` (RTSP — видеопоток) или `80/8080` (веб-интерфейс управления).
  * KeenGuard регулярно опрашивает NAT/UPnP таблицу роутера, немедленно отправляет тревогу в Telegram и веб-интерфейс и позволяет мгновенно отозвать опасный проброс.
* **Детектор утечки видео (Upload Leak):** Если камера начинает передавать наружу непрерывный видеопоток с битрейтом выше 1.5 Мбит/с на неизвестные зарубежные IP-адреса, система маркирует это как несанкционированную трансляцию в облако.
* **Скрытое сканирование сети (App Reconnaissance):** Фиксация мобильных приложений, рассылающих веерные ARP-запросы по подсети для инвентаризации домашних устройств.
* **Попытки брутфорса и подключения к запрещенным портам:** Фиксация обращений к портам `22` (SSH), `23` (Telnet — признак заражения IoT-ботнетами Mirai), `445` (SMB — распространение сетевых червей).

### 3.9. DNS & Домены (Журнал запросов и аппаратный 0.0.0.0 Sinkhole)
Самый быстрый и легкий способ блокировки рекламы и слежки без установки тяжелых прокси.

#### Принцип работы:
KeenGuard передает роутеру команду:
```
ip host adservice.google.com 0.0.0.0
```
Встроенный DNS-сервер Keenetic моментально сохраняет правило в памяти. Когда телефон, Smart TV или браузер запрашивают этот домен, роутер за долю миллисекунды возвращает адрес `0.0.0.0`. Запрос мгновенно сбрасывается без ожидания сетевых таймаутов, а страницы открываются значительно быстрее.

#### Предустановленные пакеты блокировки:
1. **Блокировка рекламы (AdBlock):**
   * Пресекает баннерные сети, тизеры, всплывающие окна и рекламные видеовставки (Яндекс Директ, AdFox, Google DoubleClick, AdSense, Mail.ru, Criteo, AppLovin, Unity Ads и др.).
   * Не ломает работу онлайн-банков, госуслуг и маркетплейсов.
2. **Отключение телеметрии Smart TV & IoT:**
   * Блокирует скрытые трекеры распознавания контента Samsung ACR, LG Smart Ad, Xiaomi MiStat/MIUI, китайские диагностические маяки (Mobicont, Pinpu).
   * Не мешает просмотру YouTube, Кинопоиска, Иви и потокового видео.

#### Двухуровневый мастер применения правил:
При нажатии *«Настроить и применить блокировку»* открывается окно с двумя секциями:
* **«Обнаружено в истории вашей сети»:** Список реальных подозрительных доменов, которые ваши устройства уже запрашивали.
* **«Рекомендованная база»:** Проверенный эталонный каталог для превентивной защиты.
Вы можете снять галочки с любых доменов перед отправкой правил на роутер.

#### Автоматическое обновление баз сигнатур:
Кнопка **«Обновить базы из интернета»** загружает свежие списки правил (AdGuard DNS filter и StevenBlack Unified Hosts) и обновляет локальную классификационную базу.

#### Интеграция с внешними DNS-провайдерами (NextDNS, Control D, AdGuard Home, Pi-hole):
Если в сети фильтрация настроена через DoH/DoT или локальный сервер, роутер не видит заблокированные запросы в таблице NAT/Conntrack, так как соединение прерывается до создания TCP-сессии.

KeenGuard напрямую интегрируется с API провайдеров:
* **NextDNS & Control D:** Подключение по API-ключу/токену, регулярный опрос журнала блокировок, классификация категорий трекеров и атрибуция по клиентам.
* **AdGuard Home & Pi-hole:** Интеграция с локальным REST API (поддержка Pi-hole v5 FTL и v6 REST API).
* **Сквозная аналитика:** Заблокированные домены отображаются в единой таблице DNS-запросов со специальными бейджами провайдеров.

### 3.10. Аудит трафика (Сессии глубокого анализа, GeoIP и PCAP)
Раздел запуска глубокого аудита сетевой активности любого выбранного устройства:
* **Сессии аудита по таймеру:** Запуск сессии на **1 минуту**, **5 минут**, **15 минут** или с ручной остановкой.
* **Мониторинг сетевых потоков (NAT Flow Monitoring):** Снятие таблицы активных соединений устройства напрямую из памяти Keenetic.
* **Проверка безопасности протоколов:** Выявление незашифрованных учетных записей и трафика (открытый HTTP, незащищенный MQTT без TLS).
* **GeoIP и облачная атрибуция:** Сопоставление IP-адресов серверов со странами и провайдерами (Amazon AWS, DigitalOcean, Microsoft Azure, VK Cloud и др.).
* **Итоговый отчет безопасности:** Расчет скоринга риска и прямая ссылка на скачивание полного сетевого дампа сессии в формате `.pcap`.

### 3.11. Настройки (9 категорий конфигурации системы)
Меню «Настройки» содержит 9 специализированных подразделов:
1. **Роутер:** IP-адрес интернет-центра Keenetic, порт RCI, логин и пароль администратора, проверка соединения, выбор физического сетевого интерфейса для сниффера Npcap/Scapy.
2. **Новые устройства:** Автоматические действия при обнаружении нового MAC-адреса (мгновенный карантин доступа в интернет WAN, изоляция от локальной сети LAN, автозапуск сессии аудита).
3. **Камеры:** Пороговый битрейт детектора утечки видео (по умолчанию 1.5 Мбит/с), доверенный IP видеорегистратора (NVR), автобан опасных UPnP-портов.
4. **Telegram & Тревоги:** Токен Telegram-бота, цифровой Chat ID, выбор способа доставки уведомлений (Cloudflare Worker шлюз для обхода блокировок или локальный SOCKS5/HTTP прокси), отправка тестового сообщения.
5. **Smart TV & Ночь:** Настройка временного окна ночного режима (например, 00:00–07:00), порог неактивности ТВ перед сном (по умолчанию 5 минут молчания), автоматическая блокировка WAN в ночные часы, утреннее оповещение при сбое перехода в сон, размер кольцевого буфера дампа (.pcap).
6. **Расписание & Дайджест:** Настройка автоматического ночного аудита безопасности всей сети (время запуска, охват: все устройства / только IoT / только недоверенные), расписание отправки суточного дайджеста.
7. **Хранилище & PCAP:** Управление объемом дискового пространства для дампов трафика, автоматическая очистка устаревших PCAP-файлов (ротация).
8. **Пресеты LAN:** Матрицы разрешений и запретов межузлового трафика с аппаратным исполнением правил (Enforcement) по пакетам и сессиям conntrack.
9. **DNS-безопасность:** Выбор службы сетевой фильтрации (NextDNS, Control D, AdGuard Home, Pi-hole), реквизиты доступа, интервал автосинхронизации (30с, 1м, 5м, 15м) и интерактивные инструкции по защите от DoT/DoH обхода.

### 3.12. Исследователь инцидентов (Incident Investigation Wizard)
Раздел интерактивного пошагового расследования сетевых инцидентов, подозрительных потоков и недавних аудитов. Доступен в боковом меню под кнопкой **«🔍 Расследования»** (с бейджем `WIZ`), а также вызывается по кнопкам `[ 🔍 Расследовать ]` из карточек устройств, журнала тревог и отчетов аудитов.

Мастер состоит из 4 последовательных аналитических уровней:

#### Шаг 1: Сетевой контекст & Корреляция DNS
* **Автоматическая корреляция:** Система сопоставляет внешние IP-адреса потоков устройства с историей локальных DNS-запросов (`dns_queries`), мгновенно определяя доменное имя узла.
* **Исключение ложных срабатываний (False Positives):** Распознавание штатного служебного трафика ОС (проверка отзыва SSL/TLS-сертификатов OCSP/CRL на порту 80, Captive Portal / NCSI проверки Windows и Android).
* **Сводный вердикт безопасности:** Информативный статус с перечислением ключевых находок (незашифрованный трафик, порты администрирования, локальные пробы).

#### Шаг 2: Внешняя разведка угроз (Threat Intelligence)
* Интерактивные карточки с прямыми защищенными ссылками на авторитетные базы киберразведки для каждого внешнего узла:
  * **VirusTotal:** Репутация IP и домена по данным 70+ антивирусных вендоров.
  * **AbuseIPDB:** Проверка жалоб на вредоносную активность, сканирование и спам.
  * **IPinfo:** Геолокация, ASN, хостинг-провайдер и тип сети (VPN, Cloud, Datacenter).
  * **Cisco Talos:** Глобальный скоринг репутации сетевого узла.
  * **WHOIS / urlscan.io:** Данные владельца доменного имени и веб-сканы.

#### Шаг 3: Действия на устройстве (Локальная диагностика по ОС)
Система генерирует индивидуальный интерактивный плейбук в зависимости от ОС подозреваемого устройства:
* **Windows:** Готовые команды PowerShell (`Get-NetTCPConnection` с выводом имени процесса и PID) и CMD (`netstat -ano`). Кнопка `📋 Копировать` для вставки в терминал в 1 клик.
* **Linux:** Команды утилит `ss -tupn` и `lsof -i`, позволяющие мгновенно выявить PID и имя демона.
* **macOS:** Команды `lsof -nP -iTCP` и интерактивный сетевой монитор `nettop`.
* **Android:** Инструкции по проверке использования данных приложениями, выявление скрытого обхода через встроенный «Персональный DNS» (DoT, порт 853) и ADB команды `dumpsys netstats`.
* **Apple iOS:** Использование встроенного «Отчета о конфиденциальности приложений» (App Privacy Report) и контроль фонового обновления.
* **Smart TV (LG webOS, Samsung Tizen, Android TV):**
  1. *Природа активности:* Разъяснение работы системных демонов прошивки ТВ (ACR / аналитика).
  2. *Отключение ACR:* Пошаговые инструкции отключения распознавания видеопотока (LG Live Plus, Samsung Viewing Information Services).
  3. *Отзыв согласий:* Отключение персонализированной рекламы (IBA) и голосовых служб.
  4. *Дежурный режим ожидания (Standby / Quick Start+):* Различие глубокого сна с обесточиванием модуля и режима ожидания, при котором сетевой чип ТВ активен круглые сутки.
* **IoT / Умный дом:** Проверка облачных привязок и локальных портов CoAP/mDNS/SSDP.

#### Шаг 4: Решение на роутере Keenetic & Физические ограничения сети
* **Физический реализм и ограничения:**
  * **VPN-туннели:** Разъяснение, почему блокировки роутера не работают внутри зашифрованного VPN-клиента на устройстве.
  * **Private DNS / DoT (порт 853):** Предупреждение об обходе мобильными телефонами DNS-сервера роутера.
  * **L2-сегмент:** Напоминание, что трафик внутри `Bridge0` идет мимо файрвола роутера.
* **Действие 1: DNS Sinkhole 0.0.0.0:** Моментальная блокировка домена на встроенном DNS Keenetic в один клик.
* **Действие 2: Профиль безопасности и изоляция:** Назначение аппаратных профилей Keenetic (`Smart TV`, `IoT`, `Доверенный`, `Карантин`) и управление доступом к WAN (блокировка/разблокировка выхода в интернет) прямо из интерфейса расследования.

## 4. Пошаговые сценарии использования

### Сценарий А: Отключение телеметрии ТВ и рекламных баннеров через Sinkhole

1. Откройте веб-интерфейс: [http://localhost:9989](http://localhost:9989).
2. В левом меню перейдите в раздел **«DNS & Домены»**.
3. Переключитесь на вкладку **«Аппаратный фильтр (Sinkhole)»**.
4. Найдите карточку **«Отключение телеметрии Smart TV & IoT»** и нажмите **«Настроить и применить блокировку»**.
5. Во всплывающем окне просмотрите список доменов:
   * Вы увидите домены, к которым ваш ТВ уже обращался, и эталонную базу (Samsung ACR, LG Smart Ad и др.).
   * При необходимости снимите галочки с сервисов, которые вы не хотите блокировать.
6. Нажмите кнопку **«Применить на Keenetic»**.
7. Правила мгновенно запишутся в память роутера. В таблице ниже появятся активные правила со статусом `0.0.0.0`.
8. Повторите процедуру для карточки **«Блокировка рекламы»**.

---

### Сценарий Б: Расследование ночного пробуждения телевизора

1. В левом меню выберите **«Smart TV & Forensics»**.
2. В блоке «Журнал ночных инцидентов» просмотрите зафиксированные события:
   * Обратите внимание на колонку «Источник»:
     * Если указано `Magic Packet (WOL)` — разверните строку и посмотрите IP/MAC отправителя (вы узнаете, какой именно телефон или планшет разбудил ТВ).
     * Если указано `Автономный опрос (Quick Start+)` — значит, телевизор не спал глубоким сном, а фоново связывался со своим сервером.
3. Если инцидент помечен как критический, нажмите кнопку **«Скачать PCAP»**.
4. Файл дампа пакетов скачается на ваш компьютер. Откройте его в Wireshark или перейдите во вкладку **«Инспектор пакетов»** и нажмите **«Открыть PCAP»** для просмотра прямо в браузере.

---

### Сценарий В: Запуск глубокого трафик-аудита с сохранением PCAP

1. Перейдите в раздел **«Устройства»** или **«Аудит трафика»**.
2. Выберите интересующее устройство (например, робот-пылесос или Smart TV).
3. Задайте длительность сессии аудита: **1 минута**, **5 минут** или **15 минут**.
4. Нажмите **«Начать аудит»**.
5. Система начнет сбор потоков соединений с роутера:
   * Вы увидите список удаленных серверов, порты, протоколы (HTTP / HTTPS / MQTT) и географическую принадлежность IP.
6. По завершении таймера система сгенерирует отчет о безопасности:
   * Предупредит, если устройство передает незашифрованные учетные данные по открытому HTTP или MQTT;
   * Предоставит прямую ссылку на скачивание полного дампа трафика за время аудита в формате `.pcap`.

### Сценарий Г: Настоящая изоляция китайской IoT-розетки или IP-камеры

1. В таблице **«Устройства»** найдите розетку или датчик.
2. В колонке «Профиль» переключите профиль на **«Локальный IoT (Zero Internet)»**.
3. В колонке «Действия» нажмите кнопку **«Заблокировать интернет»** (WAN Block).
4. Роутер Keenetic закроет устройству выход в глобальную сеть:
   * Розетка продолжит управляться локально через Home Assistant или шлюз Zigbee/Wi-Fi;
   * Данные не будут уходить на зарубежные серверы.
5. **Физическая L2-изоляция:** Помните, что пока розетка находится в общей подсети `Bridge0`, трафик между ней и вашими домашними ПК идет в обход файрвола роутера. Перейдите во вкладку **«Безопасность»** и следуйте рекомендациям *Аппаратного советника сегментации* по переводу розетки в изолированный гостевой Wi-Fi сегмент.

### Сценарий Д: Настройка Telegram-оповещений через Cloudflare Worker

1. Ознакомьтесь с подробной инструкцией в файле `docs/TELEGRAM_GATEWAY_SETUP.md`.
2. Создайте бесплатный скрипт Cloudflare Worker, проксирующий вызовы на `api.telegram.org`.
3. Откройте веб-интерфейс KeenGuard, перейдите в **«Настройки» → «Telegram & Тревоги»**.
4. Вставьте адрес вашего Worker в поле **«Шлюз Telegram API (Cloudflare Worker)»**.
5. Укажите Bot Token и Chat ID, затем нажмите **«Отправить тест в Telegram»**.
6. Получив уведомление в чате, нажмите **«Сохранить параметры Telegram»**.

### Сценарий Е: Пошаговое расследование инцидента через Wizard

1. В боковом меню перейдите в раздел **«🔍 Расследования»** (или нажмите кнопку **«🔍 Расследовать»** в строке любого подозрительного устройства, аудита или инцидента).
2. В блоке «Выбор инцидента или устройства»:
   * Выберите целевое устройство из списка или введите внешний IP-адрес / домен вручную;
   * Выберите операционную систему целевого устройства (или система определит её автоматически).
3. Нажмите кнопку **«Начать расследование»**:
   * **Шаг 1 (Сетевой контекст):** Ознакомьтесь со сводным вердиктом безопасности. Система автоматически проверит, не является ли открытый порт 80 легитимной проверкой SSL-сертификатов (OCSP/CRL) или проверкой сети Windows/Android.
   * **Шаг 2 (Разведка угроз):** Изучите внешние адреса. Кликните по ссылке **VirusTotal** или **AbuseIPDB**, чтобы мгновенно проверить репутацию подозрительного сервера.
   * **Шаг 3 (Действия на устройстве):** 
     * Для ПК (Windows/Linux/macOS): нажмите **«Копировать»** напротив команды PowerShell/терминала, запустите её на ПК и мгновенно определите PID и имя программы, удерживающей соединение.
     * Для Smart TV: следуйте пошаговым подсказкам по отключению ACR (Live Plus) и дежурного режима «Быстрый старт+».
   * **Шаг 4 (Решение на Keenetic):**
     * В блоке «Действие 1» введите домен и нажмите **«Заблокировать домен на Keenetic»** для аппаратного перенаправления в 0.0.0.0 Sinkhole;
     * В блоке «Действие 2» при необходимости назначьте аппаратный профиль (например, `Smart TV` или `В Карантин`) либо заблокируйте выход в интернет (`WAN`) в один клик.

## 5. Часто задаваемые вопросы и диагностика неисправностей (FAQ)

#### Вопрос 1: Безопасно ли вводить пароль от роутера Keenetic в KeenGuard?
**Ответ:** Абсолютно безопасно. KeenGuard работает исключительно на вашем локальном компьютере (`localhost`). Пароль сохраняется в локальном конфигурационном файле `.env` и локальной базе SQLite `data/keenguard.db`. Никакие учетные данные никуда во внешнюю сеть не передаются.

#### Вопрос 2: Будет ли нагружен процессор роутера Keenetic?
**Ответ:** Нет. KeenGuard не выполняет тяжелых операций на роутере. Он делает легкие JSON-запросы к стандартному интерфейсу Keenetic RCI раз в несколько секунд (чтение таблицы хостов из ОЗУ), что создает нагрузку на процессор роутера менее 0.1%.

#### Вопрос 3: Почему в разделе трафик-аудита пишет «Сниффер пакетов не активен»?
**Ответ:** На Windows для перехвата сетевых пакетов через библиотеку Scapy требуется установленный драйвер **Npcap**. Убедитесь, что вы скачали и установили [Npcap](https://npcap.com/#download) в режиме «WinPcap-compatible». Также проверьте в «Настройках» → «Роутер», что выбран правильный сетевой адаптер (Wi-Fi или Ethernet, через который ПК подключен к сети).

#### Вопрос 4: Как настроить бота Telegram для получения уведомлений?
1. В Telegram найдите официального бота `@BotFather` и отправьте команду `/newbot`.
2. Задайте имя и юзернейм боту, скопируйте полученный **HTTP API Token**.
3. Напишите любое сообщение своему новому боту.
4. Узнайте свой цифровой идентификатор Chat ID через бота `@userinfobot`.
5. В интерфейсе KeenGuard откройте **«Настройки» → «Telegram & Тревоги»**, вставьте токен и Chat ID.
6. Нажмите **«Отправить тест в Telegram»** — вы должны получить приветственное сообщение.
7. Нажмите **«Сохранить параметры Telegram»**.

#### Вопрос 5: Как свернуть боковое меню, чтобы видеть больше данных на экране?
Нажмите клавишу **`[`** на клавиатуре или кликните по иконке со стрелкой в верхнем или нижнем углу боковой панели. Меню свернется в компактную панель с иконками и всплывающими подсказками.

#### Вопрос 6: Как запустить KeenGuard в фоновом режиме на Windows (автозагрузка)?
Вы можете добавить ярлык файла `start.bat` в папку автозагрузки Windows:
1. Нажмите `Win + R`, введите `shell:startup` и нажмите Enter.
2. Создайте ярлык для `start.bat` в открывшейся папке.
3. В свойствах ярлыка в поле «Окно» выберите «Свернутое в значок», чтобы окно не мешало при старте системы.
